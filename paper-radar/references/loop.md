# 一份进展记录，逐轮补查与可恢复交接

协议：paper-radar-v2。当前任务以一份 RADAR.md 为协调记录；候选与逐篇证据各存一份，
不用每个角色再写一套状态/总结。用 [状态模板](../assets/radar-template.md) 初始化，
顶部保持简洁，详情引用实际来源和证据文件。历史记录在同一文件中归纳。

## 状态与写入

本次 run ID 绑定脱敏后的原始需求、日期语义、硬约束、评分版次与预算。
路径示例：配置旁的 paper-radar-results/<run-id>/；用户自定义目录优先。

- RADAR.md：顶部当前认识与下一步；逐轮实际查询、分页/引文、计数、决定与恢复位置。
- candidates.md：统一候选池，保留逐字段来源、版本关系和排除/待核验原因。
- papers/<candidate-id>.md：该材料版本的证据与逐篇评审，引用必要的原始文件。
- reading-list.md 与 selection-catalog.json：交付时才生成，绑定同一份固定编号。
- downloads/manifest.md：第二步才记录实际下载结果；文件可放用户配置的下载目录。

候选 ID 使用稳定原生 ID/DOI 的安全短标识，版本单独保存；论文 ID 不等于排序号。
不把完整 PDF、临时工具输出和私密配置重复嵌入记录；来源需能回访或由必要缓存恢复。
papers 文件中已有的证据/分项不在 RADAR.md 重抄。
没有文件系统时交付等价会话记录，恢复需取得原清单，不能凭记忆重建编号。

协调者独占更新公共记录/候选汇总/目录。发现方只写分派的批次或 papers 路径，
核验与评审只读冻结版本并返回交接，必要复核写指定隔离位置。
先等待真实完成和产物，再更新状态；角色消息只是线索，不是完成证据。

## 一轮记录什么

一轮围绕一个有实际价值的覆盖或证据缺口，不按单个 HTTP 请求记一轮。

- 开始前：轮次号、问题、计划分支/材料、预算及待执行状态。
- 搜索后：实际工具/来源、查询、日期参数、访问页/游标或种子/方向/层级、
  返回数与新增唯一数、可回访来源、完成/失败/未执行；宽池不要凭估计总数填已筛查数。
- 核验后：固定的候选与材料版本、事实核验结果、未核验项及证据位置。
- 评审后：原始主张与保守判断、分数/待评、重要分歧、补证要求。
- 收轮：实际完成与本轮耗用、可观察的剩余预算、下一项最有价值的动作及恢复位置。

分别统计来源记录、去重后 work family、具体版本、相关候选、引用新增、深读/待读。
同一篇从两源出现不是两篇新增；预印本和正式版归为 family 后仍保留材料版本。
事实核验、科学评审与独立性分别记，不用一个“通过”字段代替三者。

## 固定交接与审查

先固定本批输入清单、实际材料版本和可定位的修订标识/快照，再分派核验/评审。
可用哈希帮助标识文件；没有哈希工具也须记录来源、版本、获取时间与冻结副本位置，
不能声称哈希存在就科学正确。审查期间不覆盖材料；变更后产生新修订并只重查受影响项。

交接包含用户原话、脱敏约束、轮次、目标问题、固定输入与材料路径、工具/访问边界、
预算、返回要求和允许写入区。不向评审者预告“这篇应该高分”或要求指定答案。
记录实际 agent ID、所审修订、是否参与上游判断、上下文继承和检查范围。
参与该修订内容判断的 agent 再检查只能算自查；没有实际子 agent 则标 self_check。
共享工具/文件仍共享风险，文件绑定与角色名不是系统隔离。

## 循环的收尾条件

每轮先处理可解的常规错误/矛盾，再按证据选择下一步。
单次 API 失败、某篇得分低或没有找到足量推荐不等于整个任务结束。
不要求反复修订直到论文变成高分；保留排除、负结果和未决解释。

交付有两种明确状态：

- **本次计划完成**：计划的查询族、可用来源分页与默认两跳引用工作真实执行，
  再有连续两轮有差异的有效扩展没有新增范围内合格唯一候选。只报告观察到的有界饱和。
  仍需说明哪些候选未深读，不把发现完成当作所有论文已评审。
- **部分交付**：预算、额度、上下文或访问限制导致分支未完成，保存 partial 和可继续动作。
  不能把六轮/十篇当作科学覆盖证明；预算耗尽后不偷偷继续，也不宣称穷尽。

用户暂停标 paused；必需授权或输入缺失而无可推进工作标 blocked，说明解除条件。
不会通过后台定时任务继续，也不自动创建新聊天。正常迭代沿用已有任务授权。

## 发布清单与恢复

发布 reading-list.md 和目录前，逐项核对编号/标题/ID/版本/评分状态一致。
以下是结构说明，不是真实结果：

```json
{
  "protocol": "paper-radar-v2",
  "run_id": "synthetic-example-only",
  "catalog_revision": 1,
  "request": "Synthetic example, not a real literature result",
  "entries": [
    {
      "number": 1,
      "candidate_id": "synthetic:A",
      "title": "Synthetic paper A",
      "url": null,
      "doi": null,
      "native_id": "synthetic:A",
      "publication_version": "preprint v2",
      "reading_version": null,
      "review_revision": null,
      "recommendation": "pending_access",
      "quality": null,
      "match": null,
      "composite": null,
      "fact_check": "unverified",
      "review_mode": "self_check",
      "access": "unverified"
    }
  ]
}
```

目录是该 run 的固定交付物，不能因显示子集或重排改编号，也不预填用户选择。
发布后增加候选/重评产生新目录修订并保留旧版；改变主题/日期/硬约束另起 run，
不能让原来的“第 1 篇”悄悄对应另一篇。下载需明确 run/目录修订，歧义时只澄清身份。

恢复先读取顶部、原始任务及相关历史，检查候选、papers 与目录实际存在且版本对应，
核对预算和已接受限制。旧 agent ID 不证明实例仍活跃，旧“运行中”不证明工具还在执行。
恢复已获准的范围不重复问常规授权；先补缺失步骤，避免从第一页和第一篇无理由重跑。
