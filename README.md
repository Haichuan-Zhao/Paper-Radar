# Paper-Radar

在对话中找到值得读的论文，了解推荐依据，并下载选中的正文。

给出一个研究问题、主题或种子论文即可开始。Paper-Radar 会先检索和去重，再核查重点候选的方法、结果和关键图表，结合你的问题给出阅读顺序。每篇主要推荐说明**为什么值得读、证据在哪里、有什么局限**；只有摘要或关键材料不全的结果会标为待核验。

## 安装

在支持技能的宿主中使用安装工具，或直接复制仓库中的 `.agents/skills/paper-radar/`。例如：

```text
安装 https://github.com/Haichuan-Zhao/Paper-Radar 中的
.agents/skills/paper-radar 技能目录，沿用现有技能管理方式。
只安装，不启动检索；完成后报告实际加载位置和来源。
```

技能只包含三份文件：

```text
paper-radar/
├── SKILL.md
├── agents/openai.yaml
└── LICENSE
```

搜索、浏览器和文件工具由宿主提供，无需另配模型 API 或运行程序。仓库中的开发检查不随技能安装。

## 直接使用

筛选值得读的论文：

```text
使用 $paper-radar，找近三年关于大语言模型长上下文评测的高质量论文。
关注真实任务中的表现，接受预印本。
告诉我最值得读哪些、依据是什么，以及各自的主要局限。
```

只想先看有哪些论文，可以说“先给摘要初筛清单”。需要深入时继续说：

- “比较第 2、4 篇的实验设计，检查它们的结果能否公平比较。”
- “优先保留有独立测试集和公开代码的工作，再补查一些。”
- “只查上次之后新增的论文和版本。”
- “下载第 1、3 篇。”或“把这几篇导出为 BibTeX。”

编号对应具体论文版本，筛选和重排后保持不变。下载指定论文也可以直接开始：

```text
使用 $paper-radar，下载这篇论文的正文：<DOI、论文链接或准确题名>
```

明确选定对象后就处理下载；原版本不可得时说明可用替代稿及差异。成功后返回实际文件链接，失败项说明原因，可以继续说“只重试失败项”。

## 如何判断质量

推荐同时考虑与你的问题是否匹配，以及关键结论是否有可靠证据。实证论文关注样本、划分、对照、预算和不确定性；理论论文关注假设、证明与适用边界；综述、数据和工具论文按各自用途判断。可靠的阴性结果、复现和边界研究也可以优先推荐。

默认给“优先读、补充读、待核验”等有解释的建议。期刊分区、引用量和作者名望不能替代内容判断；缺全文也不会直接判为低质量。明确要求时才做量化评分或完整评审。规则见 [SKILL.md](.agents/skills/paper-radar/SKILL.md)。

## 可选个人配置

没有配置也能检索和获取可用的开放全文。需要复用服务、图书馆或保存位置时，可让智能体创建自由格式的 `USER_CONFIG.md`，只填需要的项：

```markdown
# Paper-Radar 个人配置
- EasyScholar key：env: PAPER_RADAR_EASYSCHOLAR_KEY
- 图书馆官网：
- 校外访问入口：
- 允许域名：
- 正文下载目录：downloads/
```

也可填写其他服务的名称、官方 API 入口和 key；空项不启用。配置优先使用本次指定文件，否则依次查当前任务目录、`~/.config/paper-radar/`，采用首个存在的 `USER_CONFIG.md`，不合并凭据。

key 支持直接填写、`env: 变量名` 或 `file: 私密文件路径`；相对凭据路径从配置目录解析。明文可能被宿主和模型读取，配置不应保存密码、Cookie 或会话令牌。仓库忽略标准配置及常见备份文件，自定义名称需自行核对忽略规则。

下载位置依次采用本次指定位置、配置的下载目录、当前任务目录下的 `downloads/`；相对下载目录从当前任务目录解析。选定位置不可写时会说明。机构登录与验证码由你在真实页面完成，单篇访问权限仍需实际核验。

## 记录与更新

简单任务直接在对话交付，长任务或批量下载按需保存一份清单或进度，不要求维护固定格式的目录。旧编号、选择与未完成项可继续沿用；不同任务的记录分开保存。

更新时核对实际安装位置和来源，保留本地定制；仓库改动不会自动刷新已复制安装的技能。检索覆盖受可用来源与访问条件影响，交付时会说明实际阅读范围和缺口。
