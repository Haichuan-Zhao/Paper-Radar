# 开发与行为验收

文件检查仅用于开发，不安装到技能目录。Python 3.9 或以上版本：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/check_project.py
.venv/bin/python -m unittest discover -s tests -v
```

这些检查覆盖分发文件、YAML、许可证、文档链接和私人配置忽略规则，不验证研究清单格式，也不能证明模型会正确筛选论文。

## 执行方法

从 [原始案例](fixtures/behavior.md) 选择与改动有关的请求。给执行者实际 SKILL.md、案例原始输入和必要临时文件；不提供本文件中的预期结果、怀疑的问题或修改理由。独立执行者需未参与被验版本的修改；由修改者执行时标 self_check。是否调用子智能体以宿主能力和授权为准。

每个独立任务使用新临时工作目录；文件用虚构题名、`synthetic:` 标识和本地文本构造，禁止读取真实配置、联网、登录或写入源码。保存实际用户输入、执行者上下文来源、规则 SHA-256、输出/生成文件、检查结果和未测项。报告放临时目录或显式指定位置，不混入正式研究结果。

对文件案例 I/J/K，准备内容可核对的本地文本或伪装文件；记录准备文件的哈希，执行后核对已有文件是否保留、最终文件是否可读及 manifest 是否符合事实。不得用没有实际执行的动作描述替代文件核对。

## 验收边界

每项记 pass/fail/not_run，并附可回查输出；文件存在不等于行为通过，规则对照不等于执行测试。独立执行者失败后修订规则的，需要对受影响案例重新运行。一次模型演练不能代表全部宿主或模型。

真实 API 分页、机构权限、在线全文下载、文献库导入、检索覆盖和评分稳定性需要另行授权及实际材料验证，未测时明确保留。性能比较采用相同请求、模型和工具条件，记录调用数、无必要追问、完成时间与遗漏；不由技能行数推断效率提升。
