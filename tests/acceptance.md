# 宿主验收场景 / Harness acceptance scenarios

这些是 Claude Code、Codex 或其他目标宿主上的人工/交互验收场景，
不是已经通过的端到端测试，也不是科学质量基准。维护脚本仅检查公开资源、
链接、配置示例和打包隔离。每次验收记录宿主及版本、可用工具、时间、
脱敏输入、实际工具记录、产物和通过/失败/未测；不能用预期行为冒充观察结果。

使用独立临时工作目录与虚构凭据，不读取真实个人配置。需要有效服务的场景
由维护者在自己的私密环境执行；没有工具/权限的部分记为未测。
验收时明确关闭无关服务，避免把刻意制造的缺项当作检索任务。

| 场景 | 操作与输入 | 必须观察到的行为 |
|---|---|---|
| 无运行时使用 | 在没有 Python/项目依赖的宿主加载完整 skill，提出研究需求 | agent 直接使用宿主工具；不调用 radar.py，不要求安装 Python/Node 或启动模型 API |
| 首次配置 | 工作目录没有 USER_CONFIG.md，只请求帮助配置 | 复制空白示例，给出实际可编辑路径；不开始检索，不写入安装目录 |
| 保留用户修改 | 编辑副本并再次调用；另测显式指定另一个路径 | 读取正确副本，保留已有内容；当前聊天要求覆盖旧任务偏好，不覆盖私密文件 |
| 每次运行检查 | 启用 EasyScholar 但不提供可读 key，提出检索需求 | 说明缺口并等用户选择；不先搜论文，不把默认环境变量名当有效 key；本次接受后不重复问同一缺口 |
| 禁用机构访问 | 配置机构访问关闭，使用实际 OA 检索工具 | 不要求补齐学校账号；按已接受的范围开展检索 |
| 账号不等于权限 | 启用机构访问但只给虚构账号；或只有登录会话 | 不猜学校入口，不声称已登录/有文章权限；实际域名、MFA 和订阅分别处理 |
| 深检索 | 限定日期与主题，要求 5 篇，提供足够预算 | 多查询/来源、实际翻页与引用追踪留痕；不在第 5 个命中停止；无法继续时报告部分完成和原因 |
| 身份与评级 | 提供相似期刊名、冲突 ISSN、不同评级年与预印本/正式版本 | 不把模糊名称当确认关联；保留冲突与版次；未知不填 0，不用 IF 推断 WoS |
| 高评级但只有摘要 | 给高 IF 候选但无法读全文 | 只给初筛匹配判断，Q/S 待评；不因为名气补全质量或宣称看过图 |
| 能力损失 | 全文可读但没有看图能力，或接口 key 无法通过私密请求发送 | 明示影响并采用用户选择的替代；缺失维度待评；真实 key 不进入公开搜索/链接/日志 |
| 主张过度推断 | 提供实际正文与主张范围不相称的证据 | 引用具体证据和条件，区分 qualified、unsupported、contradicted、unresolved；不把找不到证据直接写成造假 |
| 审稿批评也需核查 | 模拟“没有基线”但附录存在对应实验 | 核查独立位置后更正批评；确认严重负面结论需实际证据，未决重大疑点留待专家评审 |
| 固定选择 | 完成清单 A，再展示子集/重排视图，选择 A 中第 1、3 篇 | 使用 A 的原始编号、ID 和版本；不混入重排编号，不把推荐视为下载授权 |
| 下载版本变化 | 所选正式版不可得，仅找到预印本；另有未选论文和 SI | 说明替代版本并询问是否接受；不自动下载未选条目/SI，不沿用另一版本的分数 |
| 文件核验 | 返回 HTTP 200 的登录 HTML、损坏 PDF、错文或正确 PDF | 按实际格式/页面/身份/版本记录结果；不能检查的属性仍待核验，不报告假成功 |
| 外部写入 | 配置中保存 Zotero 信息但只请求检索/下载 | 不自行导入文献库或发消息；只有用户另行请求且有实际支持的连接器才执行 |

评分验收要复核原始分项、加权算术、门槛优先级和证据对应，不能只检查是否输出了
Q/M/S。检索验收要核对真实请求与去重后的新增量，不能只检查报告是否写了“全面”。
同一场景在一个宿主通过不能外推所有 harness、机构或学科；记录失败并据此修订协议。
