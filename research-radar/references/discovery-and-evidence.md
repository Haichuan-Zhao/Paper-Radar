# 深入检索与证据记录

先完成 [运行前检查](preflight.md)，再使用本次实际可用的宿主工具。
研究范围来自用户原话；不要把保存的个人偏好、示例主题或自己的方法偏好变成新任务。

## 检索设计

1. 保留研究对象、问题/任务、所需方法、应用条件和阅读目的。区分必须与偏好。
2. 规划互补查询族：领域标准术语、任务/方法组合、同义缩写、邻近问题的迁移表述。
   加入中文等相关语种，避免只用用户一句话检索。
3. 选择独立来源：综合学术索引、领域索引、原始出版社和相关预印本。
   同一 API 的重复请求不等于多个独立数据库。
4. 明确时间窗、日期依据、发表类型和严格评级/限刊条件。近年目标之外的先驱论文
   可作为比较或引用追踪依据，不能混入目标年份推荐。
5. 在新 run 目录记录计划和有效需求，不把私密配置复制进去。

选源与接口入口见 [sources.md](sources.md)。宿主可直接调用文献 MCP、搜索/fetch、
浏览器或私密 HTTP；不要求用户编程或运行固定程序。

## 执行深度

- 每个查询保留原始表达、来源、工具/页面、日期过滤、已访问页/游标和真实总数。
  查询分页到实际末页，或如实记录截断/额度/预算/故障。无游标不等于已经穷尽。
- 结果太宽时按对象/任务、时间或领域分拆查询，避免无法筛查的泛词大池。
  改写后保留原查询的限制，不能用小样本代表整个结果集。
- 检查标题、摘要和方法实际用途。缺摘要、缺关键词不是不相关的证明，保留待核验。
- 用精确 DOI/原始标题和出版社页面修补遗漏、核实年份和发表关系。
- 从不同来源/方法的相关种子追踪参考文献与被引论文，默认两跳。保存种子 ID、
  方向、层级、实际打开的引文列表和新增候选；引用数本身不证明追踪已经完成。
- 扩词来自真实相关论文和漏检原因；每轮记录新增的唯一、时间内、符合研究范围的论文。
  独立去重前后的数量不能混报。

没有预设很小的候选上限，阅读目标 count 不充当检索停止条件。
不为凑篇数纳入旁支、不因评级缺失漏掉预印本，也不假装搜索了无权访问的来源。

## 停止与覆盖

默认完成计划中的查询族、可用来源分页、种子引用追踪和补查后，
再经历两轮连续零新增相关合格唯一论文的扩展，才能称“本次计划已完成”。
这是观察到的饱和信号，不是数学穷尽或全领域召回证明。
各轮含实际查询/引用来源；复制相同查询或只写零新增不构成有效扩展。

时间、额度、访问、上下文或宿主限制导致提前停止，标为 partial，
列出未完成分支、潜在遗漏和后续可执行查询；不要把建议下一步写成已执行。
用户另选快速检索时保留缩小后的范围，不沿用“全面/完整”声明。

## 搜索日志

保存 search-log.md；一行对应一个实际检索分支或引用动作：

| 操作 ID | 来源/工具 | 查询或种子/方向/层级 | 时间窗与依据 | 已访问页/游标 | 返回/新增唯一数 | 来源证据 | 完成情况 |
|---|---|---|---|---|---|---|---|

来源证据包括实际结果页 URL、可用响应文件或连接器记录标识。工具内部临时 ID
可以作为补充，但交付时给可回访链接/文件位置。不记录带密钥的 URL。
不能枚举准确数量时填未知并解释，不把网页估计总数当实际筛查数。

交付前核对：查询族/来源是否真的执行、候选是否纳入统一集合、版本/日期是否一致、
两跳是否完成、哪些论文未读全文、何种原因停止。输出原始来源记录数量、
去重后唯一候选数量、相关候选数量、引用新增数量、完整评审与待评数量。
“单源结果集已翻页结束”与“本次多源发现计划完成”分开报告。
