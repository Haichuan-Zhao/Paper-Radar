# 选择后下载与可选文献库操作

先读 [输出与编号](outputs.md)。第一步结果完成后等待用户明确选择；
配置了目录、拥有账号或分数超过门槛都不是批量下载授权。
“下载第 1、3 篇”针对同一份清单，多个 run 不清楚时只澄清清单身份。
用户已给明确选择后按该集合执行，不重复请求同一授权。

## 宿主执行

1. 从固定目录核对编号、标题、candidate ID、DOI/原生 ID、发表/阅读版本；
   去重选择并保存选定集合，不自动加入其他高分论文。
2. 使用配置下载目录；没有文件写入/下载工具就说明无法保存，交付可访问链接或交接，
   不把“计划下载”写成“已下载”。
3. 按 [全文路线](fulltext-access.md) 获取所选正文。补充材料只有另行请求时归档；
   评价阶段读过必要 SI 不等于用户要求下载全部 SI。
4. 实际核验：文件存在、真实 PDF/可读内容、非 HTML 登录/错误页、页数，
   页首/正文标题与 DOI/原生 ID、材料版本。可用时计算 SHA-256 用于内容去重，
   哈希只证明文件内容一致，不证明论文身份或科学正确。
5. 原选版本不可得而找到另一版本时说明差异，让用户选择是否替换，再下载替代稿；
   不沿用原版本评分。实际来源、版本和任何未能执行的校验写明。
6. 确认已有相同论文/版本文件时复用或按用户偏好保存，避免覆盖不明文件。
   失败保留明确原因和下一步；不自动购买付费访问。

逐篇 manifest：run/编号、ID/版本、用户选择依据、源 URL（无凭据）、
实际文件/格式、页数与身份核验、哈希（可用时）、时间、结果/缺口。
未完成关键身份/版本核验的文件标为待验证，不称下载全部成功。

## Zotero 等可选写入

用户明确请求导入时才使用当前宿主已有的文献库连接器；不要声称存在固定本地 API
或依赖某个 Zotero 版本。写入前读取该连接器支持的操作和权限，以 DOI/版本核对重复，
确认目标库/collection 后只写入所选集合及已验证附件，不覆盖已有字段。

有元数据而无附件时分开报告。创建条目后附件失败，保存实际条目 ID，
只重试缺失的附件，不盲目重新创建。无连接器时可按请求提供 RIS/BibTeX 供手动导入，
这不等于已写入 Zotero。不得直接修改文献库数据库。

通知、邮件、定时推送属于另外的用户请求，不能因完成检索自行发送。
