# 每次运行前的配置检查

用户安装 skill 后，从 [随包配置模板](../USER_CONFIG.template.md) 复制自己的文档，
按文档配置 key、学校邮箱/账号和入口。所有说明和检查脚本随包分发；不依赖开发者
的 user-data、个人路径或账号。真实信息只存在用户的数据目录与私密环境中。

## 检查与用户决定

每次新检索前执行（run 本身也会重新检查）：

```bash
python3 radar.py preflight --profile /path/to/user-data/config.md
```

| 状态 / 退出码 | 宿主行为 |
|---|---|
| ready_for_discovery / 0 | 配置可供检索，继续第一步；远端 key 有效性、会话和订阅仍以实际使用为准 |
| needs_user_choice / 3 | 列出缺项、实际影响和配置入口，一次性让用户选择先补全，或接受列明的缺口继续；等待决定后再检索 |
| blocked / 2 | 必需研究问题/日期/语法或路由无效；从用户意图补全可推断字段，无法推断的询问用户，修正后重查 |

使用宿主的问题工具或简短对话呈现选择，例如：“缺少 EasyScholar key，评级将待核验；
OpenAlex 缺 key，多页检索受限。先补全配置，还是在这些限制下继续？”
这次询问来自用户要求的运行前检查流程。不要把用户要求找论文本身当作接受缺口，
也不要擅自选择继续。用户选择补全时保留任务，完成配置后重新检查。

用户明确选择继续后，执行：

```bash
python3 radar.py run --profile /path/to/user-data/config.md --out /path/to/new-run --continue-with-gaps
```

该参数记录已取得的决定，不是由配置或网页授予的许可。正常 run 有缺项时返回 3，
不创建运行目录、不发送检索请求、不发通知。继续时只应用本次临时降级并保存
preflight.json；不改用户配置文件、不移除用户的 IF/WoS 等要求。缺评级的门槛
保持待核验，付费访问和论文质量不因此被假定。

检查启用的 EasyScholar/OpenAlex 凭据、本地期刊表、Unpaywall 联系邮箱、机构
路由及账号密码对；只返回状态，不返回内容。未启用的可选服务按用户配置记录，
不要求每人注册所有服务。过期 key、额度和实际登录无法由离线检查证明；首次
真实请求失败时如实记录，若需改动范围或新增凭据，再让用户选择处理方式。

同一检索任务中的补查轮次可以沿用用户对相同缺口的明确决定，但每轮仍重新检查；
新缺口或新任务需要新的决定。用户选择具体下载论文后，宿主也应重查当前访问
配置和真实会话；不因检索时已配置过就假定下载时仍有权限。

## 宿主能力与深度

Python 检查不能探测所有 harness 工具。宿主另行确认可用来源、HTTPS、全文/PDF
读取、图片查看与文件保存能力；缺能力时说明对深度、评分或下载的影响，让用户
决定补充能力还是接受受限结果。无需先登录所有数据库来完成这个检查。

默认 search.mode=deep。count 是最终希望阅读的篇数，不是元数据搜集上限；
默认不设分页上限。深度流程与停止依据见 [检索策略](discovery-and-evidence.md)。
检索前说明计划覆盖哪些方法和来源；检索后报告实际覆盖及尚未完成的部分。
